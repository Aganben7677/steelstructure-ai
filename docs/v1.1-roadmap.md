# Steelstructure.ai V1.1 Roadmap

## V1.1 name

**Steelstructure.ai Workbench Foundation**

## Strategic direction

V1.1 should move Steelstructure.ai from a public industry information website toward a practical steel structure AI workbench.

The goal is not to build a large generic steel encyclopedia. The goal is to create a focused assistant layer for steel structure professionals who need to review bid documents, identify technical requirements, track project opportunities, and reuse fabrication knowledge.

## V1.1 positioning statement

Steelstructure.ai is a steel structure industry intelligence and AI workbench for EPC project tracking, bid document review, technical requirement extraction, estimation support, and fabrication knowledge reuse.

## Primary user groups

1. Steel structure fabricators
2. Marketing and estimation teams
3. EPC sourcing and procurement teams
4. Project engineers and technical managers
5. Business development teams tracking global industrial projects

## Core V1.1 outcomes

By the end of V1.1, the website should make three things clear:

1. What Steelstructure.ai is
2. What problem it solves
3. How it can become useful in a real steel structure bidding or project review workflow

## V1.1 workstreams

### 1. Homepage positioning upgrade

Update the homepage hero and key sections to explain the platform more directly.

Recommended homepage message:

> Steelstructure.ai helps steel structure teams track global project opportunities, review bid documents, extract technical requirements, and build reusable fabrication knowledge.

Key homepage additions:

- Clear product positioning
- Short value proposition for fabricators
- Short value proposition for EPC / sourcing teams
- Entry point for future AI workbench / demo
- Link to project maps, knowledge base, and itinerary archive

### 2. AI workbench placeholder

Create a visible but lightweight workbench entry page.

Suggested page:

- `workbench.html`

Suggested modules:

- Bid Document Review
- Technical Requirement Extraction
- Clarification Drafting
- Estimation Checklist
- Material / Bolt / Coating Notes
- Project Risk Summary

Initial version can be static. It only needs to communicate the intended workflow.

### 3. Bid review demo workflow

Prepare one simple demo flow:

1. Upload or reference inquiry documents
2. Extract scope, standards, material requirements, coating, welding, bolts, testing, packing, and delivery terms
3. Generate a bid review checklist
4. Generate clarification questions
5. Generate estimation support notes

This should become the first real Steelstructure.ai use case.

### 4. Project intelligence structure

Improve project tracking pages so future data can be maintained more easily.

Recommended actions:

- Move inline project data into JSON files
- Add fields for project sector, region, EPC, owner, status, estimated value, steel relevance, source date, and confidence level
- Keep maps and cards generated from structured data

### 5. Knowledge base structure

Convert the knowledge page into a reusable steel structure knowledge index.

Suggested categories:

- Materials
- Bolting
- Welding
- Coating and galvanizing
- Fireproofing
- Trial assembly
- Packing and logistics
- Inspection and testing
- International standards
- Project-specific lessons learned

### 6. Launch archive and evidence

Keep launch documentation in the repository:

- `docs/launch-log.md`
- `launch-evidence/README.md`
- Screenshot files when available

### 7. SEO and sharing basics

Add or improve:

- Page titles
- Meta descriptions
- Open Graph preview tags
- Favicon / social preview image
- Canonical URL pointing to `https://steelstructure.ai/`
- Simple sitemap
- Robots.txt

### 8. Maintenance workflow

Create a repeatable update process:

- Daily brief update checklist
- Project update checklist
- New knowledge note template
- Data source log
- Link check routine

## Success criteria

V1.1 is successful when a visitor can understand within 30 seconds that Steelstructure.ai is not only an information website, but a future AI workbench for steel structure bidding, project tracking, and technical knowledge reuse.

## Product principle

Start narrow. Make one professional workflow useful before adding more features.

The first strong workflow should be:

> Bid inquiry document review → technical requirement extraction → clarification questions → estimation checklist.
